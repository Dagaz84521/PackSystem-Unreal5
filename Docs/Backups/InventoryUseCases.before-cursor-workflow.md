# Inventory 用例与接口设计

本文档用于先整理会改变物品存储的游戏场景，再从这些场景中提取 `InventoryComponent`、`AggregateInventoryComponent` 和 `SlottedInventoryComponent` 的接口。

当前阶段只考虑单机下的库存逻辑，不考虑网络同步。

## 使用方法

1. 从“场景清单”中选一个场景。
2. 复制“用例模板”并填写。
3. 明确操作前后的存储变化，以及成功和失败结果。
4. 将用例需要的能力记入“候选接口”。
5. 多个用例都需要同一种能力时，再确定正式函数。

## 用例记录

下面的记录顺序与总表一致。`INV-007` 是完整填写示例，其余用例保留待填写项。

### 第一阶段：玩家背包与 UI

完成玩家自己背包中的格子操作和界面交互。第一阶段只处理同一个 SlottedInventoryComponent 内的变化；UI 负责表达玩家意图并显示结果，不直接修改 Entry 或 Payload。

#### INV-001 移动物品到另一个格子

**目的**

玩家将一个格子中的完整物品堆移动到同一背包的另一个空格子。

**输入**

- 来源：同一 Slotted 容器中的来源格子。
- 目标：同一 Slotted 容器中的目标格子。
- 物品：来源格子当前保存的完整 Payload。
- 数量：来源格子的全部数量。
- 指定格子：必须同时指定来源格子和目标格子。

**前置条件**

- 来源和目标属于同一个 SlottedInventoryComponent。
- 来源和目标是两个不同且有效的格子。
- 来源格子保存着有效物品。
- 目标格子为空。
- 目标格子允许放入来源物品。

**操作规则**

- 本用例只移动完整物品堆，不处理部分数量。
- 本用例不自动寻找其他格子。
- 目标非空时不执行移动；UI 应根据情况请求交换或合并。
- 移动不改变 Item Instance 和数量，只改变 Payload 所在格子。
- 成功后来源格子保持有效但 Payload 为空，目标格子保存原 Payload。
- UI 应提交一次完整移动请求，不能分别清空和填充两个格子。

**成功时的变化**

```text
操作前：
Slot 2 = 木材 x20
Slot 7 = 空

操作后：
Slot 2 = 空
Slot 7 = 木材 x20
```

**失败情况**

| 失败原因 | 期望结果 |
| --- | --- |
| 来源或目标格子无效 | 不改变任何格子 |
| 来源和目标相同 | 不改变库存，可视为无操作 |
| 来源格子为空 | 不改变库存 |
| 目标格子非空 | 不改变库存，由调用方决定是否交换或合并 |
| 目标格子拒绝该物品 | 不改变库存 |
| 两个格子不属于同一背包 | 不改变库存 |

**操作结果需要提供的信息**

- 是否成功。
- 失败原因。
- 来源和目标格子的 Handle。
- 实际移动数量。
- 是否属于无操作。

**候选接口**

| 能力 | 查询或修改 | 可能属于 |
| --- | --- | --- |
| 根据 Slot Index 获取稳定的 Entry Handle | 查询 | SlottedInventoryComponent |
| 判断格子是否为空 | 查询 | SlottedInventoryComponent |
| 判断物品能否放入指定格子 | 查询 | SlottedInventoryComponent |
| 将完整 Payload 移动到空格子 | 修改 | SlottedInventoryComponent |
| 返回来源和目标格子的操作结果 | 结果类型 | Slotted Inventory |
| 两个格子完成修改后再通知 UI | 内部修改 | InventoryComponent 或 SlottedInventoryComponent |

**测试场景**

- 完整堆叠移动到空格，成功。
- 数量为 1 的物品移动到空格，成功。
- 来源和目标相同，不改变库存。
- 来源为空，失败。
- 目标非空，失败。
- Handle 无效或属于其他背包，失败。
- 操作后 Item Instance 和数量均未改变。
- UI 收到通知时，两个格子都已经是最终状态。

#### INV-002 交换两个格子的物品

**目的**

玩家交换同一背包中两个非空格子的完整物品堆。

**输入**

- 来源：同一 Slotted 容器中的格子 A。
- 目标：同一 Slotted 容器中的格子 B。
- 物品：两个格子当前保存的完整 Payload。
- 数量：两个格子的全部数量。
- 指定格子：必须指定格子 A 和格子 B。

**前置条件**

- 两个格子属于同一个 SlottedInventoryComponent。
- 两个格子不同且有效。
- 两个格子都保存着有效物品。
- 两个格子分别允许接收对方的物品。

**操作规则**

- 交换只改变两个 Payload 所在的位置，不改变 Item Instance 和数量。
- 空目标使用“移动物品到另一个格子”，不属于本用例。
- 两堆物品相容时，UI 默认优先请求合并；明确要求交换时才执行本用例。
- 交换前必须同时验证两个方向的放置规则。
- 任一方向不允许放置时，整个交换失败。
- UI 只提交一次交换请求，不分别执行两次移动。

**成功时的变化**

```text
操作前：
Slot 2 = 木材 x20
Slot 7 = 石头 x12

操作后：
Slot 2 = 石头 x12
Slot 7 = 木材 x20
```

**失败情况**

| 失败原因 | 期望结果 |
| --- | --- |
| 任一格子无效 | 不改变任何格子 |
| 两个格子相同 | 不改变库存，可视为无操作 |
| 任一格子为空 | 不改变库存 |
| 任一格子拒绝对方物品 | 不改变库存 |
| 两个格子不属于同一背包 | 不改变库存 |

**操作结果需要提供的信息**

- 是否成功。
- 失败原因。
- 两个受影响格子的 Handle。
- 是否属于无操作。

**候选接口**

| 能力 | 查询或修改 | 可能属于 |
| --- | --- | --- |
| 同时判断两个物品能否放入对方格子 | 查询 | SlottedInventoryComponent |
| 交换两个格子的完整 Payload | 修改 | SlottedInventoryComponent |
| 返回两个受影响格子的操作结果 | 结果类型 | Slotted Inventory |
| 一次性提交两个格子的最终状态 | 内部修改 | SlottedInventoryComponent |

**测试场景**

- 两个不同物品堆交换成功。
- 两个运行时状态不同的物品堆交换成功。
- 任一格子为空，失败。
- 任一格子拒绝对方物品，整体失败。
- 两个 Handle 相同，不改变库存。
- Handle 无效或来自其他背包，失败。
- 交换后两个 Item Instance 和数量均保持不变。

#### INV-003 拆分物品堆叠

**目的**

玩家从一个物品堆中取出指定数量，并在同一背包的空格子中形成独立物品堆。

**输入**

- 来源：原物品堆所在格子。
- 目标：同一 Slotted 容器中的目标空格子。
- 物品：来源格子中的物品。
- 数量：玩家希望拆出的数量。
- 指定格子：必须指定来源和目标格子。

**前置条件**

- 来源和目标属于同一个 SlottedInventoryComponent。
- 来源和目标不同且有效。
- 来源保存着数量大于 1 的有效物品堆。
- 目标为空并允许放入该物品。
- 拆分数量大于 0，且严格小于来源数量。

**操作规则**

- 拆分数量必须完整满足，不允许部分成功。
- 拆分后两堆数量之和必须等于拆分前数量。
- 来源保留原 Item Instance，并减少数量。
- 目标使用 DuplicateInstance 创建独立 Item Instance，避免共享可变状态。
- 拆出数量不得超过该物品的单格堆叠上限。
- 拆出全部数量应使用移动用例。
- 不自动寻找其他空格子。

**成功时的变化**

```text
操作前：
Slot 2 = 木材 x20
Slot 7 = 空
拆分数量 = 6

操作后：
Slot 2 = 木材 x14（保留原 Item Instance）
Slot 7 = 木材 x6（使用独立 Item Instance）
```

**失败情况**

| 失败原因 | 期望结果 |
| --- | --- |
| 来源或目标格子无效 | 不改变任何格子 |
| 来源和目标相同 | 不改变库存 |
| 来源为空或数量小于 2 | 不改变库存 |
| 拆分数量小于等于 0 | 不改变库存 |
| 拆分数量大于等于来源数量 | 不改变库存 |
| 目标格子非空或拒绝物品 | 不改变库存 |
| Item Instance 复制失败 | 不改变库存 |

**操作结果需要提供的信息**

- 是否成功。
- 失败原因。
- 请求数量和实际拆分数量。
- 来源和目标格子的 Handle。
- 新物品堆的 Payload（调用方需要时）。

**候选接口**

| 能力 | 查询或修改 | 可能属于 |
| --- | --- | --- |
| 判断指定数量能否拆出 | 查询 | SlottedInventoryComponent |
| 判断目标空格能否接收物品 | 查询 | SlottedInventoryComponent |
| 将指定数量拆分到目标空格 | 修改 | SlottedInventoryComponent |
| 复制 Item Instance | 内部能力 | InventoryItemInstance |
| 返回数量和两个格子的操作结果 | 结果类型 | Slotted Inventory |

**测试场景**

- 从数量 20 中拆出 6，得到 14 和 6。
- 拆出 1，成功。
- 来源数量为 1，失败。
- 拆分 0、负数、等于或大于来源数量，失败。
- 目标非空或拒绝物品，失败。
- 拆分后总数量守恒。
- 修改拆分后任一 Item Instance，不影响另一堆。

#### INV-004 合并物品堆叠

**目的**

玩家将来源格子中的部分或全部物品合并到目标格子的相容物品堆中。

**输入**

- 来源：来源物品堆所在格子。
- 目标：目标物品堆所在格子。
- 物品：两个格子中的相容物品。
- 数量：请求从来源移动的数量；未指定时尝试移动全部。
- 指定格子：必须指定来源和目标格子。

**前置条件**

- 来源和目标属于同一个 SlottedInventoryComponent。
- 来源和目标不同且有效。
- 两个格子都保存有效物品。
- 两个 Item Instance 满足现有匹配规则。
- 目标尚未达到单格堆叠上限。

**操作规则**

- 实际合并数量取请求数量、来源数量和目标剩余容量的最小值。
- 目标容量不足时允许部分成功。
- 目标保留自己的 Item Instance，只增加数量。
- 来源未被完全合并时保留原 Item Instance 并减少数量。
- 来源被完全合并时清空来源格子。
- 物品不相容时不执行合并；UI 可以改为请求交换。
- 合并前后两个格子的总数量必须相等。
- 不自动寻找其他可合并格子。

**成功时的变化**

```text
操作前：
Slot 2 = 木材 x12
Slot 7 = 木材 x18
单格上限 = 20
请求合并数量 = 12

操作后：
Slot 2 = 木材 x10
Slot 7 = 木材 x20
结果 = 部分成功，实际合并 2
```

**失败情况**

| 失败原因 | 期望结果 |
| --- | --- |
| 来源或目标格子无效 | 不改变任何格子 |
| 来源和目标相同 | 不改变库存 |
| 任一格子为空 | 不改变库存 |
| 请求数量小于等于 0 | 不改变库存 |
| 两个 Item Instance 不相容 | 不改变库存 |
| 目标达到堆叠上限 | 不改变库存 |
| 无法取得有效堆叠上限 | 不改变库存 |

**操作结果需要提供的信息**

- 成功、部分成功或失败。
- 请求数量、实际合并数量和未完成数量。
- 失败原因。
- 来源和目标格子的 Handle。
- 来源格子是否变为空。

**候选接口**

| 能力 | 查询或修改 | 可能属于 |
| --- | --- | --- |
| 判断两个格子的物品能否合并 | 查询 | SlottedInventoryComponent |
| 查询目标堆叠的剩余容量 | 查询 | SlottedInventoryComponent |
| 将来源指定数量合并到目标 | 修改 | SlottedInventoryComponent |
| 返回数量状态和两个格子的操作结果 | 结果类型 | Slotted Inventory |
| 读取单格堆叠上限 | 查询 | InventoryItemDefinition |

**测试场景**

- 来源全部合并后清空来源格子。
- 目标容量不足，只合并一部分。
- 请求数量小于来源数量，按请求数量合并。
- 请求数量大于来源数量，最多合并来源全部数量。
- 物品不相容或目标已满，失败。
- 同一格子与自己合并，不改变库存。
- 合并前后总数量守恒。
- 完全合并时目标保留自己的 Item Instance。

#### INV-005 自动整理物品

**目的**

玩家整理自己的背包，使相容堆叠尽可能合并，并将非空格子紧凑排列到背包前部。

**输入**

- 来源：当前 SlottedInventoryComponent 的全部格子。
- 目标：整理后的同一个容器。
- 物品：容器中的全部物品。
- 数量：不适用。
- 指定格子：不指定，由整理规则决定。

**前置条件**

- 背包组件及格子数据有效。
- 当前没有由 UI 暂存且尚未落入任何格子的拖拽物品。
- 所有非空 Payload 都满足基本数据约束。

**操作规则**

- 第一阶段只做两件事：合并相容堆叠，以及把空格移到末尾。
- 按当前 Slot 顺序从前向后处理，将后续相容堆叠尽量合并到前面。
- 目标堆叠不能超过单格堆叠上限。
- 合并后保持剩余非空堆叠的相对顺序，并依次放到前面的格子。
- 当前不按名称、类型、稀有度或重量排序；以后可用独立策略扩展。
- 整理不能创建、销毁或改变物品总数量。
- 已经符合规则时返回成功，但不产生数据变化。
- UI 不应观察到临时排列，可在完成后整体刷新。

**成功时的变化**

```text
操作前：
Slot 0 = 木材 x12
Slot 1 = 空
Slot 2 = 石头 x5
Slot 3 = 木材 x8
Slot 4 = 空
木材单格上限 = 20

操作后：
Slot 0 = 木材 x20
Slot 1 = 石头 x5
Slot 2 = 空
Slot 3 = 空
Slot 4 = 空
```

**失败情况**

| 失败原因 | 期望结果 |
| --- | --- |
| 背包或格子数据无效 | 不改变库存 |
| 存在结构不合法的 Payload | 不改变库存并报告错误 |
| 无法取得物品的堆叠规则 | 不改变库存 |
| 整理所需的 Item Instance 复制失败 | 不改变库存 |
| UI 仍持有未放置的临时 Payload | 拒绝整理，先处理暂存物品 |

**操作结果需要提供的信息**

- 是否成功。
- 是否实际发生变化。
- 失败原因。
- 发生变化的格子数量或 Handle 集合。
- 合并的物品堆数量（仅在需要时）。

**候选接口**

| 能力 | 查询或修改 | 可能属于 |
| --- | --- | --- |
| 获取按 Slot 顺序排列的全部格子 | 查询 | SlottedInventoryComponent |
| 规划整理后的全部 Slot Payload | 内部能力 | SlottedInventoryComponent |
| 判断整理前后状态是否相同 | 内部能力 | SlottedInventoryComponent |
| 一次性应用整理后的格子状态 | 修改 | SlottedInventoryComponent |
| 通知 UI 整体重建 | 事件 | InventoryComponent.OnInventoryReset |
| 返回变化状态和受影响格子 | 结果类型 | Slotted Inventory |

**测试场景**

- 空背包或只有一堆物品，整理成功且无变化。
- 中间存在空格，非空格子向前紧凑排列。

#### INV-007 拾取世界物品（示例）

**目的**

玩家拾取世界中的物品，并将背包能够容纳的数量存入背包。

**输入**

- 来源：世界中的物品对象
- 目标：玩家背包
- 物品：世界物品所代表的 Item Definition 或 Item Instance
- 数量：世界物品当前可拾取数量
- 指定格子：无，交由背包自动选择

**前置条件**

- 世界物品有效且尚未被销毁。
- 玩家拥有可用的背包组件。
- 拾取行为本身已经由交互系统判定为有效。

**操作规则**

- 优先合并到尚未达到堆叠上限的已有 Entry 或 Slot。
- 剩余物品再放入可用的新 Entry 或空 Slot。
- 允许部分成功：背包只能接收一部分时，只拾取实际能够容纳的数量。
- 背包完全无法接收时，不改变背包和世界物品。
- InventoryComponent 只负责存储变化，不负责判断交互距离或播放拾取动画。

**成功时的变化**

```text
操作前：世界中有 10 个木材，玩家背包能够再容纳 6 个木材。
操作后：玩家背包增加 6 个木材，世界物品剩余 4 个木材。
```

**失败情况**

| 失败原因 | 期望结果 |
| --- | --- |
| 世界物品无效 | 不改变库存 |
| 请求数量小于等于零 | 不改变库存 |
| 玩家没有背包组件 | 不改变世界物品 |
| 背包没有任何可用空间 | 不改变背包和世界物品 |
| 物品不符合背包限制 | 不改变背包和世界物品 |

**操作结果需要提供的信息**

- 是否添加了物品。
- 实际添加数量。
- 未能添加的剩余数量。
- 失败原因。
- 受影响的 Entry 或 Slot（如果调用方确实需要）。

**候选接口**

| 能力 | 查询或修改 | 可能属于 |
| --- | --- | --- |
| 查询背包最多能够接收多少数量 | 查询 | InventoryComponent |
| 向背包添加物品并返回实际添加数量 | 修改 | InventoryComponent |
| 查找可以继续堆叠的位置 | 查询 | 具体存储实现 |
| 查找可用的新 Entry 或空 Slot | 查询 | 具体存储实现 |
| 根据实际添加数量减少或销毁世界物品 | 修改 | 拾取用例或世界物品 |

**测试场景**

- 背包为空，全部拾取成功。
- 已有相同物品的未满堆叠，优先合并。
- 已有堆叠填满后，剩余数量进入新位置。
- 空间不足，只拾取一部分。
- 背包已满，完全无法拾取。
- 请求数量无效。

## 基本不变量

- 物品数量不能小于零。
- 数量为零的 Entry 不应继续占用存储位置。
- 堆叠数量不能超过物品的堆叠上限。
- 一个格子同时最多保存一个物品堆叠。
- 物品必须满足容器和格子的限制规则。
- 失败的操作不能只完成一半。
- 跨容器转移不能凭空增加或丢失物品。
- 缩小容量时不能静默删除超出容量的物品。
